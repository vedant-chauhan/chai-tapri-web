# K. Phased Implementation Roadmap

Status: **Proposed.** Durations are indicative for one full-stack developer plus part-time design. `[Assumption]`

| Phase | Deliverables | Depends on | Acceptance criteria | Major risks |
|---|---|---|---|---|
| **0. Decisions & access** (≈1 wk, mostly client time) | Answers to blocking questions. Signed-off ADRs. Accounts created by the owner: domain, Cloudflare, DB, payment provider, Uber Direct (test mode), Google Cloud. POS vendor contact | This report | All "Blocking" questions in CLIENT_QUESTIONS answered or explicitly deferred. ADR-0001…0006 Confirmed | Slow client answers. POS has no API |
| **1. Design** (≈2–3 wks, overlaps phase 2) | Design tokens, type/colour tests with the real logo, mobile-first wireframes → hi-fi for Home, Menu+item sheet, Checkout, Order status, Admin dashboard. Copy deck. Photo-shoot brief | Logo files, photo rights, menu data | Client approves the hi-fi mobile + desktop. Accessibility contrast checked | Atmosphere photos not ready → interim crops |
| **2. Foundation** (≈1.5–2 wks on the low-cost Cloudflare setup; see design/PHASE-4-FOUNDATION.md) | Repo, CI gates, environments, DB + migrations, auth with MFA, error monitoring, health endpoint, design-system primitives | Phase 0 | A trivial change deploys to staging through CI. Staff can log in with MFA | — |
| **3. Content site + live status** (≈1.5 wks) | Home, Our Story, Visit, legal page shells, hours admin + availability engine (fully unit-tested), notices, reviews section | Menu data, copy, hours confirmed | Status chip correct for every case in BUSINESS_RULES §1.4. Lighthouse mobile ≥ 90. axe clean | Google API terms/quotas |
| **4. Menu & cart** (≈1.5 wks) | Menu admin (or POS catalog sync), modifiers, allergens, sold-out toggles, cart with server pricing | Menu master decision (Q5) | Server rejects tampered prices. Modifier min/max enforced. Sold-out blocks checkout | Menu data quality |
| **5. Pickup checkout + payments** (≈2 wks) | Slots/capacity, checkout, payment integration, webhooks, outbox, confirmation email, order status page, admin order board, refunds, reconciliation job | Payment ADR, legal texts (draft) | Full pickup E2E in test mode. Duplicate-webhook and double-click tests pass. Refund flow works | Payment/POS coupling (Square vs Stripe) |
| **6. POS integration** (≈1–2 wks, varies) | `PosAdapter` P1 or P2 implementation, catalog sync (if POS is master), status sync, failure alerts | POS confirmed + credentials/sandbox | Paid web orders appear in the POS/kitchen within 30 s. Failures alert staff within 3 min | Vendor API limits, partner approval delays |
| **7. Uber Direct delivery** (≈1.5–2 wks) | Address autocomplete + geocode, quotes, fee policy, delivery creation, webhooks, tracking, failure handling, delivery admin | Uber account approved, delivery-fee policy (Q2) | Robocourier sandbox runs through all statuses. Failure drills pass. One real delivery in production rehearsal | Account approval time. Late-night courier supply. Economics |
| **8. Hardening & launch** (≈1 wk) | Security review, accessibility audit, performance tuning, final legal texts, UAT with staff, launch rehearsal, runbooks, staff training | All above | Production-readiness checklist passes. Owner approves launch | Last-minute content gaps |
| **9. Post-launch (Later)** | SMS notifications, accounts/reorder, promo codes, loyalty, GBP hours sync, merchandise shop | Real usage data | Measured against G4 goals | Scope creep |

**Critical path (updated 15 Oct 2026):** slice-1 design approval → owner creates accounts (Cloudflare Workers Paid, Neon, Stripe in the business's name, Resend, domain — see setup/OWNER-ACCOUNTS.md) → foundation → pickup ordering (phases 2–5). The POS isn't on the critical path any more: launch uses the staff order board (ADR-0003), and phase 6 happens whenever a POS is chosen. Uber Direct API access (F3) runs in parallel for phase 7.
**Earliest useful release:** phases 2–5 with POS pattern P3 (admin board) = **pickup ordering live**. Delivery and full POS sync follow. Shipping pickup first lowers risk and starts saving marketplace commission sooner.
